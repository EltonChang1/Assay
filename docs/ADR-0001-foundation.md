# ADR 0001 — Local research foundation and execution boundaries

Date: October 16, 2026. Status: accepted design; implementation and validation are incremental. This foundation is not a completed analytical runtime, G0 environment gate, G1 oracle gate, or security certification.

## Context

The source checkout is inside OneDrive on a Windows development machine. The study needs independently scoreable numerical claims, authoritative execution evidence, controlled release, reproducible offline development, and later isolated model/tool execution. A small local system is sufficient; network services and a custom UI are not prerequisites.

## Decisions

1. **Start with a Python package and CLI.** Use Python 3.12, `uv`, a committed lockfile, Pydantic contracts, pytest, Hypothesis, Ruff, and mypy for the first foundation. DuckDB is a development dependency for trusted fixed-query regression tests; it is not an analyst execution interface. Record exact resolved dependencies in [the inventory](DEPENDENCIES.md). Add worker execution, Arrow/Parquet, SQLite persistence, Inspect, and the export adapter only with the corresponding feature and checks. The offline foundation must not require model credentials or incur charges.
2. **Keep mutable state outside synchronized source.** The Windows default is `%LOCALAPPDATA%/TraceFrameSafetyLab`; Linux uses `$XDG_STATE_HOME/TraceFrameSafetyLab` or `~/.local/state/TraceFrameSafetyLab`. `SAFETY_LAB_STATE_DIR` provides an explicit override. Configuration rejects the checkout, OneDrive-named directories, and configured OneDrive roots. Keep mutable databases, scratch files, logs, and active runs outside the repository and recognized sync roots. Use completed immutable allowlisted exports for sharing. Path validation reduces accidental placement; it cannot discover every third-party sync provider or replace deployment review. Windows-to-Linux public input path mapping has now been exercised with the local Docker Linux engine; other deployments still require their own environment checks.
3. **Separate public contracts from private evaluation.** Public TaskSpec and claim contracts define permitted slots and semantics without expected answers. Exposed development task cards document hand-calculated examples; worker-mounted public bundles omit expected answers and private builder records. Final-test seeds, expected answers, attack labels, private logs, and evaluator configuration belong outside actor/reviewer mounts and prompts. A final-test evaluator must run in a separate restricted process/context; putting source in an `evaluator/` directory or ignoring files in Git is insufficient. Oracle outcomes are measurement after release, never an input to the publication policy.
4. **Do not add a host SQL shortcut.** No analyst SQL is executed by the host, by TraceFrame's `tf.sql`, or by a fallback when Docker is missing. The implemented gateway validates the allowed grammar and relations, dispatches every query to a container worker, captures results itself, assigns receipt IDs, and preserves full bounded outputs with explicit preview truncation. An AST allowlist and hardened database configuration are complementary controls, not substitutes for isolation.
5. **Make execution capability explicit and fail closed.** Diagnostics may report package/runtime information and probe Docker availability without launching a model. A missing Docker client/daemon or failed capability probe prevents commands that require an isolated worker; it must not silently enable local SQL. Docker availability alone proves neither worker provisioning nor restricted execution. The local pinned image builds, starts, and stops with validated public input mapping. Separate container tests now pass G2 locally for the initial sales-schema worker, covering denied host/file/network access, resource enforcement, useful queries, authoritative receipts, and isolation regressions; [implementation status](IMPLEMENTATION_STATUS.md) records the evidence and scope. The diagnostic reports readiness separately and does not assess isolation.
6. **Keep authority in trusted modules.** Start with one bounded SQLite metadata writer and content-addressed artifacts when persistence is implemented. Only the trusted publisher may release deterministic report bytes bound to the exact approved revision, source versions, and active attempt. The actor, reviewer, export adapter, viewer, and private scorer receive no alternate publication authority. Missing mandatory prerequisites withhold output; `unknown` is never silently converted to `pass`.
7. **Use adapters after the core works.** Inspect is the planned initial evaluation harness, but its host tool wrapper does not isolate a query by itself. TraceFrame receives a verified projection in a dedicated process/directory per run and preserves lab IDs and limitations. Its mutable evidence files and source-discovery regular expressions are not security controls. AMOS remains a later capability-reviewed integration with unresolved notice provenance; its inspected payment fixture is not a general task API. No upstream code is copied into this foundation.

## Consequences and next evidence

The foundation can validate contracts, configuration, deterministic synthetic fixtures, and local diagnostics without claiming that untrusted tools are safe to run. Installation and smoke checks establish package behavior only. A development reference calculation does not complete G1 until the planned hand calculations, incorrect analyses, alternative correct analyses, and oracle separation checks are exercised and recorded.

The SQL grammar, container worker, and receipt path are implemented, and local CPU/memory/time/output, host/private-data, network, and cleanup checks pass for the initial worker. Claim verification and publication fencing are implemented offline ([ADR 0003](ADR-0003-publication.md)); before the first analyst episode, add gateway admission fencing and lease expiry. Before any paid episode, configure a priced model entry, explicit spending cap, combined oversight budget, and in-flight reservation accounting. No paid evaluation, host SQL, or private final-test scoring is implied by this execution milestone.

Pilot decisions remain open: exact analyst/reviewer models, dated prices, spending/token/call caps, materiality thresholds, usefulness margin, benchmark sample size, and whether external benchmark data are needed. Freeze them with prompts, policies, checks, attacks, images, lockfile, and analysis before confirmation. Five percentage points and the plan's episode counts remain planning candidates, not measured or preregistered commitments.

The lab's own distribution license has not been selected. Upstream licenses do not choose it automatically. Exact dependency pins, dataset rights, upstream notices, sanitized export contents, and private-data exposure need review before distribution; see [the dependency inventory](DEPENDENCIES.md), [security policy](../SECURITY.md), and [implementation plan](../IMPLEMENTATION_PLAN.md).
