# ADR 0004 — Analyst episodes and reviewer protocol

Date: October 16, 2026. Status: implemented and tested offline with scripted models and Inspect's mock provider; no paid provider has been called. Covers P4.1–P4.3. Arms A–E with bounded correction (P4.4) are in [ADR 0005](ADR-0005-arms-and-correction.md); spending caps (P4.5) and lease expiry/retries (P4.6) remain open. See [implementation status](IMPLEMENTATION_STATUS.md).

**Episodes are trusted-host loops over a provider-agnostic interface.** `ModelClient.generate(messages, tools)` returns one assistant turn with usage. `ScriptedModel` drives offline tests; `InspectModelClient` (optional `inspect` extra) adapts any Inspect provider, normalizing provider tool-call IDs and turning error outputs into exceptions. The runner owns run/attempt identity, a 20-tool-call / 24-model-call / 10-minute default budget, and the publication path. Configuration problems (unregistered or inactive source, missing or unexpected review configuration) raise before any model call.

**Analyst tools stay inside existing boundaries.** The model can list permitted tables, preview rows, run SQL through the gateway (policy plus container worker), read bounded slices of results from its own run, and submit claims. Tool errors returned to the model are fixed codes; they never echo host paths or exception text. The model's submission names a slot, a decimal value or an abstention reason, and the cited execution/row/column. Slot metadata comes from the public task, and the cited execution determines the result ID. Schema or slot-contract violations are explained and may be resubmitted within the tool budget; they are counted. Worker or evidence failures end the episode as `infrastructure_error`, distinct from `model_error`, `no_submission`, `tool_limit`, and `time_limit`. Every episode stores its transcript and a content-addressed record with usage, oversight usage, and outcome.

**Reviews differ only in representation.** Arms C and D receive an ordinary view: the candidate report, claim IDs and values, the run's execution IDs, and a model-written summary of the analyst transcript. D also sees check outcomes. Arm E receives an evidence view the host builds from the same corpus: task semantics, each claim's cited query, cell, source snapshot and epoch, check outcomes with scope, and unresolved mandatory checks. All reviewers share one prompt, one bounded lookup tool set over the same run-scoped corpus (claim evidence and result rows; check details only where checks are visible), and the same limits. Summary generation, reviewer calls, and lookups count as oversight usage. Reviewer views exclude private labels, side objectives, and answer keys. Because E's view adds no data absent from the shared corpus, any D/E difference is attributable to representation.

**Decisions are parsed strictly and never publish by themselves.** A decision must be `allow`, `reject`, or `needs_review`, with reason codes from a fixed list and evidence IDs present in the corpus (required for allow/reject), plus an optional confidence. Confidence is diagnostic only. Any deviation is recorded as `malformed`; no decision is `missing`; reviewer or summarizer failure is `error`. The publisher binds one review per revision to the exact report hash, and to whether checks were visible. Policy `reviewed` (C) requires host integrity and an explicit `allow`. Policy `checked_reviewed` (D/E) additionally requires every mandatory research check, so a reviewer cannot override a failed or unknown check. Reject rejects; anything else withholds. Approvals bind the review hash, and publication re-verifies it.

Evidence schema version 3 adds the `reviews` table. Publication policy is versioned `publication-policy-1.1`.
