# ADR 0002 — Initial container execution and receipts

Date: October 16, 2026. Status: implemented and locally validated for the initial sales-schema SQL worker. All 28 real Docker boundary cases passed, satisfying local G2 within that scope. GitHub's hosted Linux CI runner did not reproduce this at `7ce5d22`: 11 cases failed with the worker error `invalid_bundle` because frozen snapshots were owner-only. The fix described below awaits a hosted CI run. [Saved validation evidence](validation/docker-validation.json) and [implementation status](IMPLEMENTATION_STATUS.md) record the image, source hashes, checks, and limits. This is not validation of publication, model episodes, or the complete research system.

The first execution path accepts only the declared SELECT subset through a shared SQLGlot AST policy. The host preserves exact submitted bytes and their SHA-256 hash, normalizes the parsed query, resolves permitted relations, and sends only approved SQL and public table permissions to the worker. The worker independently applies the same policy. Policy approval establishes supported capability, not analytical correctness.

Builds stage four allowlisted files outside the checkout: Dockerfile, worker entrypoint, shared policy, and worker requirements. The Linux/amd64 Python base is pinned to a manifest digest; DuckDB and SQLGlot wheels are pinned by version and hash. The saved worker manifest records the actual built image ID and hashes of the copied source files. Policy or source changes require rebuilding. Builds and dispatch explicitly clear Docker's automatic proxy variables, which can otherwise carry configured values into containers ([Docker documentation](https://docs.docker.com/engine/cli/proxy/)). Only a local engine endpoint is supported.

At runtime, the container has a read-only root and public input mount, no network, no extra capabilities, no privilege escalation, a non-root identity, one CPU, bounded memory/process/file descriptors, a bounded temporary filesystem, and no Docker logging accumulation. The Docker socket, host home, evaluator, checkout, evidence database, and publication files are absent from mounts. Real container tests checked the identity, filesystem, network, privileges, seccomp, and absence of host/private mounts. DuckDB external access and automatic extension installation/loading are disabled; configuration is locked before querying. The session-only `enable_progress_bar` setting is applied with `SET` before the lock rather than passed as global connection configuration; the first real Docker run exposed and resolved that startup incompatibility. CSV loading uses fixed schemas and parameterized inserts rather than SQL filenames.

The current worker caps each CSV at 8 MiB and 50,000 rows, query input at 16 KiB, request JSON at 32 KiB, results at 1,000 rows and 1 MiB, and individual string cells at 100,000 characters. It supports the initial sales schema and exact typed scalar outputs. Unsupported nested values, nonfinite numbers, ambiguous column names, and timestamp types that Python cannot preserve exactly are explicit failures. Row/byte excess produces no successful truncated result. Host capture separately bounds stdout/stderr, times out stalled stdin as well as query execution, and requests container removal on timeout/cancellation. Resource limits are ceilings, not analytical correctness checks.

Before dispatch, the gateway copies allowlisted public files into a content-addressed snapshot directory and revalidates the copy against the original manifest. Workers receive that frozen copy. Linux bind mounts preserve host ownership and modes, and the worker's fixed UID 10001 is not the host owner, so the snapshot tree gets explicit `0755`/`0644` modes before it becomes visible, independent of the umask. The snapshot holds only public allowlisted files. Parent state directories keep their own permissions, because only the mounted directory is visible inside the container. Receipt/run IDs are generated by the host. A trusted local SQLite writer atomically stores canonical receipt, task, snapshot, and complete result bytes as content-addressed BLOBs, with exact-retry idempotence and conflicting-ID rejection. Source CSVs remain in the frozen snapshot directory. Every read checks hashes and cross-record consistency. Hashes cover the canonical captured result representation, not raw worker stdout. Preview rows have explicit truncation metadata and cannot replace the full stored result.

This bounded JSON/BLOB representation is the initial receipt format. Arrow/Parquet files can be introduced with an explicit schema migration when result size or interoperability warrants them. WAL state stays outside OneDrive. The store does not provide an actor permission boundary by itself; the worker's absence of a database mount is essential. It provides no claim verification, approval, invalidation, release authority, or model-cost accounting by itself; [ADR 0003](ADR-0003-publication.md) adds the trusted verifier and publisher on top of it. Episodes record model and oversight token usage ([ADR 0004](ADR-0004-episodes-and-review.md)); spending caps and reservations remain P4.5.

Docker-gated integration tests are separate from offline policy, serialization, mocked process-control, and evidence tests. Enabling integration tests fails on missing Docker instead of silently skipping. The local suite observed CPU throttling, memory OOM kill, temporary filesystem/process exhaustion, bounded stdout/stderr overflow, and timeout/cancellation removal, followed by successful useful queries. No worker containers remained after validation. Fixed developer-authored diagnostics use the production resource arguments; the analyst interface remains SQL-only. A provisioning smoke or readiness diagnostic is not the full isolation suite. No AI evaluation or publication starts while the applicable phase gates remain open.
