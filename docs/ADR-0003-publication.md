# ADR 0003 — Claim verification, publication, and audit projection

Date: October 16, 2026. Status: implemented with offline local tests for the initial sales schema. The genuine query results in these tests come from the real gateway path with an in-process DuckDB stand-in for the container; container isolation evidence remains the separate [Docker suite](ADR-0002-execution.md). This is not validation of model episodes, reviewer arms, budgets, or final-test isolation. See [implementation status](IMPLEMENTATION_STATUS.md).

**Verification is layered and never collapses into one flag.** The `sales-public-1.0` checker returns separate host-integrity checks (report contract, declared slots, evidence identity, execution success) and mandatory research checks (exact cell binding, slot contract, SQL metric, units, grain, population, public missingness), plus advisory data diagnostics. Evidence identity re-reads hash-checked receipts, results, and frozen public CSVs, and requires the same run, task, snapshot, result, and declared dependencies. A claim binds only to its designated row and column within the slot tolerance; the same number elsewhere fails. The SQL profile recognizes a narrow set of relational shapes, including order-level aggregation, `EXISTS`, and deduplicated item joins. Anything else returns `unknown`, including conditional `SUM(CASE ...)` arguments that may be correct. Authentic duplicated-join output therefore passes every host check and binding, then fails grain. `SUM(DISTINCT amount)` fails the metric check. Public rows are used only for missingness and join cardinality, never to recompute a gold answer.

**Reports are rendered only from typed slots.** The `structured-text-1.0` renderer emits fixed templates over declared required/supporting slots with exact decimal formatting. Abstention reasons and any other model text stay in audit records. Undeclared, duplicated, or metadata-contradicting claims are refused before a revision exists.

**One trusted publisher owns the lifecycle.** Evidence schema version 2 adds publisher indexes: a source registry with epochs and history, run leases and attempts with fencing tokens, report revisions, claims, approvals, releases with separate validity, and a latest-release index. Immutable record bytes remain content-addressed artifacts. Revisions move `submitted → checked → approved | rejected | needs_review → published`, and pending current-data revisions become `stale` when their source changes. `checked` replaces the plan's transient `checking` label because checks run outside the writer lock and the stored state means "checked, awaiting decision". Each transition runs in one SQLite writer transaction. It re-verifies that the caller's lease is the run's active, unrevoked attempt, that the revision belongs to that attempt, and that the revision is in the required state.

**Policy is deterministic and conservative.** Host integrity is mandatory in every profile and cannot be overridden. The `checked` profile also requires every research check; `baseline` (arm A) records research checks without using them. A failure rejects. An unknown, missing, or duplicated check, a checker-version mismatch, or a check bundle bound to other report bytes yields `needs_review`, which never releases without runtime human review. Approval binds report hash, rendered hash, check bundle hash, policy version, source epoch, attempt, and fencing token.

**Publication and invalidation compare the same epoch.** Registering a different active snapshot increments the source epoch. In the same transaction, it marks current-data releases `stale`, removes them from the latest index, and stales pending current-data revisions. Publication rechecks the epoch and active snapshot for current-data reports, or registered history for historical reports, inside its own transaction. Stale releases keep their immutable release record and original bytes behind explicit archival access; release events and benchmark scores are never rewritten. Rendered bytes are stored at submission but served only through committed release rows. Because the release row, latest index, status, edges, and event commit together in SQLite, no file-promotion outbox is needed. A failed or killed publication leaves no visible release, and a retry is idempotent.

**Fencing is a Phase 3 minimum.** Starting an attempt revokes the previous token; cancellation clears the active attempt. An approval from a canceled or superseded attempt cannot publish, and the new attempt cannot publish the old attempt's revision. Gateway result admission does not yet require a lease, and budget reservations and leases with expiry are not implemented; both complete with P4.6. The gateway now accepts a runner-supplied `run_id`, validated before dispatch, so one episode's queries share a run identity.

**TraceFrame export is a researcher-audit projection.** `Publisher.audit_bundle` assembles verified records; `export_traceframe` projects them in a fresh subprocess using the exact pinned upstream commit, verifying the MIT notice hash. The subprocess gets a minimal environment, a disposable home/cache directory because upstream plotting imports resolve one at import time, and only the public bundle. Every exported file is manifested and hashed, a lossless `lab-records.json` companion preserves fields TraceFrame cannot represent, and unknown checks stay out of TraceFrame's boolean check table. Export failure never changes publication state; identical retries reuse a verified export, and a conflicting bundle is refused. A report citing an execution missing from the store cannot currently be exported, because the adapter requires every referenced execution.

Tests cover the plan's worked-milestone scenarios: correct release, duplicated-join rejection with a baseline release scored incorrect by the private evaluator, mismatched cell binding, unrelated-metric citation, fenced delayed approval, current-to-stale invalidation with archival history, and the equal-value counterexample. They also cover concurrent publishers, publication racing a source update, cancellation racing publication, an aborted release transaction, and a hard process kill in the middle of publication.
